## 根本原因（影响全部20+4幅图）

执行环境的出站网络代理策略拦截了对几乎所有外部数据源域名的直接访问，包括：
`api.eia.gov`、`fred.stlouisfed.org`、`data.sec.gov`、`api.bls.gov`、`emp.lbl.gov`、
`www.pjm.com`、以及通用网页抓取工具 WebFetch 本身（连 en.wikipedia.org 都被拦截）。
唯一可用的外部信息渠道是 WebSearch（仅返回搜索摘要片段+来源链接）。

这意味着：文档标注为"无阻塞、优先"的阶段一任务（T1-T5，全部是免费公开API）实际上
**在本环境内同样被阻塞**——不是因为数据不存在或需要付费/注册，而是纯粹的网络策略限制。
这是本次执行与其它17个缺口（真正的付费墙/注册墙/数据不存在）性质不同的一类问题：
**一旦更换到有出站网络权限的环境（例如本地终端的Claude Code CLI），T1-T5可以立即产出真实完整数据**。
`src/fetch/` 下四个脚本已经写好并通过语法检查，代码正确性不是问题，缺的只是网络权限。
